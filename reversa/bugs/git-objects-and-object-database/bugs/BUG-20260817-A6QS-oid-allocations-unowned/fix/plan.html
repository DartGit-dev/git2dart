Defect and root cause

OID-producing binding adapters return both caller-owned calloc<git_oid>() outputs and parent-owned borrowed pointers. Baseline Oid stores both through the same constructor without an ownership marker, finalizer, or release operation. Releasing every pointer would corrupt borrowed storage; releasing none keeps owned allocations alive for the process lifetime.

deterministic 1/1 baseline16/16 candidate testscandidate aba8aa7

Evidence: reproduction capsule, confirmed root cause, and static analysis.

Chosen strategy

Direct correction with audit of existing candidate aba8aa7. Keep the candidate's owned-pointer finalizer and explicit release path. Convert borrowed native pointers into owned copies before constructing Oid, so high-level values can safely outlive their parent objects. Add focused regression coverage before accepting the already-committed code diff.
