Fix plan · #24 BUG-20260817-H7NP

git-objects-and-object-database · 2026-08-26 · severity: high · priority: P1

Defect and root cause

BlobWriteStream.writeString advertises UTF-8 but converts String.codeUnits directly to Uint8List. Dart code units are UTF-16; values above 255 are truncated and multi-byte UTF-8 sequences are never emitted.

Root-cause state: supported. Evidence: static analysis and affected method. The planned red test will confirm the full runtime path.

Chosen strategy

Direct correction. The defect has one causal explanation, and Dart’s standard UTF-8 encoder precisely implements the documented contract. No multi-agent debate is warranted.

Correction change set

CHGTypeArtifactPurpose
CHG-001testtest/blob_test.dartProve streamed UTF-8 round-trips Cyrillic, emoji, combining characters, and ASCII.
CHG-002codelib/src/writestream.dartEncode string input with the standard UTF-8 codec before native stream writing.

Planned tests

Reproduction: stream a mixed Unicode string, commit it, and show that the current implementation does not round-trip its content or UTF-8 bytes.

Regression: the same focused test asserts content and bytes equal the UTF-8 encoding after the correction. It covers ASCII, Cyrillic, emoji, and combining characters.

Risk and exclusions

Change risk: low. One documented convenience method changes from an incorrect conversion to the standard encoder; raw write(Uint8List) is untouched. The public API signature and native ABI do not change.

Out of scope: automatic repair of previously corrupted blobs. Truncation lost the source code units, so safe reconstruction is impossible without caller-provided originals.
