Defect and confirmed cause

Forty typed git_libgit2_opts_* calls in Libgit2 discard their integer result. When libgit2 rejects an option, the facade can return normally or read an output buffer instead of immediately translating the current native error. The existing packMaxObjectSize getter and setter already demonstrate the required pattern.

deterministic 1/1raw negative result observedpublic wrapper returned normallyno valid option state mutated

Evidence: reproduction capsule, root cause, static analysis, and selected strategy.

Chosen strategy

Direct correction. Capture each fallible global-option status and call checkErrorAndThrow before interpreting outputs or returning. This reuses the existing error contract; no new abstraction, public API, dependency, data repair, or specification addendum is proposed.

Scope of CHG-002

The affected calls are limited to one facade: mmap limits (6), config search paths (2), cache controls (5), template and SSL paths (3), user agent (2), safety and verification toggles (12), pack settings (4), HTTP expect/continue (2), extensions (2), and owner validation (2).

Explicitly out of scope: QWMA option-structure initializers, callback concurrency, native ABI changes, option transactions, and any refactoring unrelated to immediate result checks.

Specification and delivery boundary

The preliminary recommendation is spec-correta: BR-NP-03, FR-NP-04, FL-NP-05, and ADR-004 already require immediate native-error translation. The mandatory verdict remains a later human decision after Gate 2. Package publication, merge, and version assignment are also outside this plan.

This is a proposal, not an applied correction. Approving this plan authorizes preparation of the Gate 1 test diff only; it does not authorize source or test changes.
