#28 · BUG-20260817-Q6JV

medium P2 Worktree lock inspection does not dispose reason buffer.

Defect and confirmed root cause

Historically, isLocked passed a native git_buf to libgit2 and returned the boolean result without releasing storage that libgit2 may allocate for the lock reason. Commit e2d8bb4 wraps the native query in try/finally and calls git_buf_dispose on every path.

Evidence state: confirmed by historical diff and current-head source audit.

Chosen strategy

Direct, minimal audit. The required disposal is already present in the current branch. No new product patch is proposed; validation exercises unlocked, locked, and unlocked-again worktree states.

CHG-001codelib/src/bindings/worktree.dartAlready applied in e2d8bb4: dispose the reason buffer in guaranteed cleanup after the lock-state query.

Planned proof

  • Regression: test/worktree_test.dart locks, queries, unlocks, and re-queries a local worktree.
  • Ownership proof: source audit verifies git_buf_dispose(reason) resides in the finally block covering the native call.
  • Quality: focused Flutter test, focused analyzer, historical-diff integrity, and branch-containment checks.

Risk and boundaries

Low — one native output buffer is balanced inside its adapter. No public API, data migration, network operation, or broad cleanup is in scope.
