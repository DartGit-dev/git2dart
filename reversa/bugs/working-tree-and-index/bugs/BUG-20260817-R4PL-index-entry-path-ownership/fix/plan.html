Defect and confirmed root cause

Every IndexEntry creation route wraps a libgit2-owned, non-modifiable git_index_entry*. The path, oid, and mode setters then mutate that borrowed structure; the path setter additionally replaces a libgit2-owned string pointer with an unmanaged Dart allocation.

Evidence: static analysis and ownership trace.

Chosen strategy

Preserve the existing mutable public API by copying every borrowed entry into one independently owned native allocation. Store the UTF-8 path in the same allocation, replace the whole owned block on path changes, and release the current block exactly once through explicit disposal plus a finalizer safety net. This avoids a breaking removal of setters and keeps Index.add, addFromBuffer, and conflict APIs receiving a complete native entry.

Planned tests

Reproduction: assert that setters do not alter the libgit2-owned source entry before Index.add.

Regression: repeated path replacement keeps exactly one live owned block; Index.add consumes the mutated copy; disposal is balanced and idempotent.

Risk and exclusions

Medium: all IndexEntry projections change ownership, but the source API and native call shape remain compatible.

Excluded: generated declarations, dependencies, binaries, broad refactors, commits, publication, and unrelated bug fixes.
