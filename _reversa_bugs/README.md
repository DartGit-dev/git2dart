# Reversa Bug Registry

> Generated by Reversa on 2026-08-16. This file defines the bug registry contract for this project.
> Source of truth: each `<context>/bugs/<ID>/bug.md`. Everything under `generated/` is a regenerable projection.

## Project configuration

```yaml
closure_policy: package
control_mode: gated
```

- `closure_policy: package` requires passing regression tests, a specification verdict, merge, and publication of the fixed package version, including required backports.
- `control_mode: gated` allows reading, isolated reproduction, and diagnosis without additional approval. Applying tests, applying a change set, changing the effective specification, using an external harness with project access, or performing a destructive operation requires approval.

## Structure

Bugs are grouped by context, meaning a feature, module, or use case in the reporter's language. A context directory is created only when an inspection or report produces artifacts.

```text
_reversa_bugs/
|-- README.md
|-- taxonomy.yaml
`-- <context>/
    |-- bugs/BUG-<date>-<suffix>-<slug>/
    |   |-- bug.md
    |   `-- evidence/
    |-- inspections/<inspection>/
    `-- generated/
```

## Lifecycle

`status` progresses from `open` to `active` to `resolved`. `phase` records the current activity. Blocking is a condition, not a status. Every closure records a `resolution_kind`.

When the closure policy is satisfied, the bug receives `DONE.md` and becomes read-only. A recurrence is recorded as a new bug related by `regression-of`.

## Traceability rule

Every bug must identify:

1. The effective specification section that defines expected behavior. A missing specification is labeled `spec-gap`.
2. The affected code and, after investigation, the confirmed root cause with evidence.
3. Reproduction and regression tests.

A bug cannot be resolved as fixed while its specification traceability, confirmed root cause, or regression tests are empty.

## Agent protocol

1. `/reversa-debugger` and `/reversa-depth-inspection` diagnose and register. They never fix.
2. The original specification is never edited. A specification change is an immutable versioned addendum with a recorded human decision.
3. Code and specification changes are recorded together in the bug resolution.
4. Restricted security bugs stay out of generated views and external harnesses.
5. Relationships and root causes retain their epistemic state. A hypothesis is not a fact.

## Conventions

- Canonical ID: `BUG-<YYYYMMDD>-<suffix>`.
- References use canonical IDs.
- Evidence belongs in `evidence/`; large logs are linked rather than embedded.
- The complete schema is defined by the Reversa debugger skill.
